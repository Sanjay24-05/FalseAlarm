# Tech debt remediation plan

Spec: the 2026-11-25 tech debt audit (21 items, four phases). Each task names its audit item as `#n`.

## Global Constraints

- Every behavior change starts with a test that fails for the stated reason. Config, CI and generated files are exempt.
- Both shipped scenarios keep their verdicts: `account_compromise` is `confirmed_threat`, `benign_vpn_login` is `likely_benign`.
- Verdicts and reports come only from stored evidence. The model never writes them.
- When evidence is incomplete, fail toward `suspicious`, never toward `likely_benign`.
- The offline demo keeps working with no environment variables set.
- README changes land with the behavior they describe.
- Backend suite: `backend/.venv/Scripts/python.exe -m pytest -q` from `backend`.
- No push, no merge, no license choice, no repository rename.

## Review Focus

- False negatives: any input that reaches `likely_benign` while attacker activity is stored, truncated, or unattributed.
- Attribution when usernames or hostnames are missing, blank, differently cased, or machine accounts.
- Existing SQLite files created before the migration work.
- A hostile or looping model in the planner.
- The console still working against the API with default settings (Origin, Host and content-type checks through the Vite proxy).

## Phase 1: trustworthy verdicts

### Task 1: CI (#3)
Files: `.github/workflows/ci.yml`, `backend/pyproject.toml` (ruff config, dev extra).
- Backend job: Python 3.12, install, ruff, pytest. Frontend job: `npm ci`, typecheck, build. `permissions: contents: read`.
- Expected: ruff and pytest pass locally; workflow YAML parses.

### Task 2: Scoped queries (#1)
Files: `planner/playbooks.py`, `agent/tools.py`, `agent/loop.py`, `errors.py`, `tests/test_scoping.py`.
- An alert with only an IP filters every log query by that IP.
- `execute_tool` raises `UnscopedQueryError` for a query with no user, host or IOC. The loop records a `rejected` step.
- Expected: an unrelated IP-only alert stores no other user's evidence and is not `confirmed_threat`.

### Task 3: Evidence identity (#2)
Files: `agent/observe.py`, `agent/loop.py`, `tests/test_evidence_identity.py`.
- Two events differing in any normalized field are both kept, in either order. Re-running a query adds nothing. Identical rows in one result are separate events. A repeated threat-intel lookup does not duplicate.

### Task 4: Every successful login counts (#4)
Files: `assessment/rules.py`, `tests/test_assessment.py`, `README.md`.
- `likely_benign` requires every success to be from a supported source and no repeated failures from an untrusted source.
- A success from an untrusted source after three or more failures from it escalates.
- Expected: VPN login at 11:00 plus external brute force at 13:56 is not `likely_benign` and escalates.

### Task 5: Attribution (#5)
Files: `assessment/rules.py`, `tests/test_assessment.py`, `README.md`.
- Later-action signals need the alert's user (or, with no user or a machine account on the event, its host or source), must not precede the access, and must not be blocked by the firewall.
- Harm that fails those tests still blocks `likely_benign` and is reported as a material gap.

### Task 6: Report citations (#6)
Files: `reports/render.py`, `tests/test_reports.py`.
- Text from alerts or logs that looks like an evidence id is defanged (`ev[-]9999`) and cannot trigger the template or pass as a citation.

### Task 7: Truncation (#7)
Files: `connectors/file_connector.py`, `agent/loop.py`, `assessment/rules.py`, tests, `README.md`.
- Truncation keeps the newest events in chronological order.
- A truncated query is a material gap and blocks `likely_benign`.

## Phase 2: safe to run

### Task 8: Input robustness and ingest race (#8)
Files: `api/routes.py`, `main.py`, `ingest/__init__.py`, `util.py`, `tests/test_input_robustness.py`.
- Invalid UTF-8, lone surrogates, out-of-range dates, deep nesting, NaN/Infinity: 422 `{errors: [...]}`, nothing stored.
- FastAPI validation errors use the same shape. Concurrent identical ingests yield one new alert and duplicates.

### Task 9: LLM trust boundary (#9)
Files: `planner/llm.py`, `planner/playbooks.py`, `agent/loop.py`, `tests/test_llm_planner.py`, `README.md`.
- A model-supplied `question_id` is ignored. A question is answered only by a query that covers the playbook's own filters.
- A model `finish` with questions open, an unscoped query, or a repeat of an executed query is replaced by the playbook action and audited.

### Task 10: Run lifecycle (#10)
Files: `db.py`, `agent/loop.py`, `main.py`, `api/routes.py`, `tests/test_lifecycle.py`, `README.md`, `frontend/src/lib/format.ts`.
- Startup marks leftover running investigations `failed` with `stop_reason` `interrupted`.
- Starting an alert that is already running returns the running id and schedules nothing.

### Task 11: LLM deadline and logging (#11)
Files: `planner/llm.py`, `agent/loop.py`, `tests/test_llm_planner.py`.
- Each call's timeout is capped by the time left; no call starts after the deadline. Failures are logged and audited by type, without the key or response body.

### Task 12: Dependencies (#12)
Files: `backend/requirements.lock`, `pyproject.toml`, `frontend/package-lock.json`, CI, `README.md`.
- Locked, updated, OSV and `npm audit` clean.

### Task 13: Indicators (#13)
Files: `ingest/iocs.py`, `ingest/__init__.py`, `util.py`, `domain/models.py`, `connectors/file_connector.py`, `agent/*`, tests.
- Usernames and file names are not domains; a URL contributes only its host. IPv6 is extracted. An invalid IP field is dropped with a warning. Documentation ranges count as external. Indicators discovered after the first lookup are looked up.

### Task 14: Imports, dead code, README (#20)
Files: `agent/allowlist.py` and `agent/context.py` (moved), `errors.py`, `settings.py`, `README.md`, `tests/test_imports.py`.
- Every module imports standalone. Unused names are gone. README has no contradictions or machine-specific paths.

## Phase 3: wider coverage

### Task 15: Scenario corpus (#14)
Files: `data/scenarios/*`, `tests/test_scenarios.py`, `README.md`.
- Each playbook (authentication, malware, outbound, generic) has one malicious and one benign scenario; a parametrized test runs them all.

### Task 16: Frontend tests and lint (#15)
Files: `frontend/package.json`, `vite.config.ts`, `src/**/*.test.ts(x)`, CI.
- vitest covers the API client, polling hook and queue page; a linter runs; both are in CI.

### Task 17: Investigation history (#16)
Files: `db.py`, `service.py`, `api/routes.py`, `tests/test_history.py`, frontend queue and detail pages.
- `GET /api/alerts/{id}/investigations`; queue verdict and alert page link to past runs.

## Phase 4: ready to grow

### Task 18: Access protection (#17)
Files: `security.py`, `main.py`, `settings.py`, `api/routes.py`, `vite.config.ts`, `tests/test_security.py`, `README.md`.
- Unknown Host: 400. Unsafe method with a foreign Origin: 403. Non-JSON alert body: 415. Optional `FALSE_ALARM_API_TOKEN` bearer token, off by default, forwarded by the Vite proxy.

### Task 19: Database layer (#18)
Files: `db.py`, `api/routes.py`, `tests/test_db.py`.
- Versioned migrations run once per database; verdict is a column, backfilled; the queue parses no investigation documents; upload does not block the event loop.

### Task 20: Typed API and assessment split (#19)
Files: `api/schemas.py`, `api/routes.py`, `scripts/generate_types.py`, `frontend/src/generated/api.ts`, frontend types/normalize, `assessment/*`.
- TypeScript types are generated from the backend models; a test fails when they drift. `assess()` becomes small functions with no behavior change.

### Task 21: Connector seam (#21)
Files: `connectors/*`, `agent/tools.py`, `agent/loop.py`, `settings.py`, `scenarios.py`, `tests/test_connector_registry.py`, `README.md`.
- A `Connector` protocol and registry; a second connector reading JSON Lines exports, selected by setting, which does not read demo data.
